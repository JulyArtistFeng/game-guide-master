# 交付前质量检查清单

交付前完整读取，逐项验证。本清单是"可能失败"的验证动作，不是走形式。

---

## 一、内容完整性

- [ ] **章节数正确**：docs +fetch --scope outline --max-depth 1 确认所有计划章节都存在，标题无遗漏。
- [ ] **用户点名系统全覆盖**：keyword搜索确认用户明确提到的每个系统/机制/道具都有对应章节。
- [ ] **原帖未覆盖内容已补充**：对照第一步的"原帖没说什么"清单，逐项确认已补充。
- [ ] **每章有"本章怎么用"callout**：抽查3~5章，确认开头有引导callout。
- [ ] **数据表格化**：配方、掉落、属性、对比类内容用了table，不是散文罗列。
- [ ] **流程类内容有步骤**：Boss打法、获取流程等拆成Step/有序列表，不是一段文字。

## 二、事实核验

- [ ] **关键数字有来源**：配方、掉落率、HP、周期天数等数字，要么来自可信来源，要么标注"以游戏内为准"。
- [ ] **无编造数据**：全文搜索"约X%"、"X天"等数字，确认每个都有依据或标注。
- [ ] **版本差异已处理**：单机vs联机、本体vs DLC、旧版vs当前版的差异已用callout注明。
- [ ] **常见错误已修正**：对照已知的攻略常见错误（如饥荒月相周期、切斯特形态），确认文档用的是正确版本。
- [ ] **命名统一**：同一物品/机制全文用同一个名称，不混用不同译名。

## 三、图片质量

- [ ] **每章有图（除总览/目录章）**：outline确认有图章节数符合预期。
- [ ] **图片是真实游戏截图**：抽查3~5张，确认不是立绘、宣传图、AI生成图。
- [ ] **图片位置正确**：图片紧接h1标题之后，不在章节末尾堆积。
- [ ] **caption有意义**：每张图的caption说明画面内容，不是空的或"图片1"。
- [ ] **无重水印/营销卡片**：抽查图片，确认没有大面积水印或宣传卡片。
- [ ] **版本正确**：图片是对应版本（联机版不是单机版，本体不是DLC）。
- [ ] **含密集文字图片清晰可读**：仅抽查含表格/配方/数据/UI文字的图片（如食谱表、科技栏、制作栏、地图），放大后文字不模糊、可读；模糊的已替换为清晰版或改用文档内表格。**纯游戏画面（场景/战斗/Boss/地形）不检查分辨率，低分辨率也可保留。**

## 四、结构与格式

- [ ] **XML无泄漏**：全文搜索"<h1"、"<table"等，确认没有未解析的XML代码裸露在正文里。
- [ ] **无占位符残留**：搜索"TODO"、"XXX"、"待补充"、"[占位]"等，确认没有残留。
- [ ] **标签配平**：抽查复杂章节（含table+callout+grid的），确认开闭标签配对。
- [ ] **无内部执行过程**：正文不出现"已路由"、"根据skill"、"lark-cli"、"agent"等内部术语。
- [ ] **标题编号连续**：章节编号（一、二、三...或1、2、3...）无跳号、无重复。

## 五、用户特定要求

- [ ] **用户要求删除的内容已清除**：如出处文案、AI生成声明等，keyword搜索确认无残留。
- [ ] **用户要求保留的内容未动**：正文攻略内容、表格、图片未被误删。
- [ ] **用户偏好已满足**：如语言风格、详细程度、配图要求等。

## 六、可访问性

- [ ] **文档链接可打开**：present_files交付的链接有效。
- [ ] **图片在文档中正常显示**：fetch确认img块有src/token，不是破损。
- [ ] **表格在移动端可读**：列数不过多（建议≤5列），关键信息不被截断。

---

## 验证方法（工具调用）

### 结构验证

```bash
# 确认章节数和标题
lark-cli docs +fetch --doc "DOC_ID" --scope outline --max-depth 1

# 确认关键内容存在
lark-cli docs +fetch --doc "DOC_ID" --scope keyword --keyword "关键词1|关键词2" --context-before 0 --context-after 0
```

### 图片验证

```bash
# 抽查某章图片位置和caption
lark-cli docs +fetch --doc "DOC_ID" --scope keyword --keyword "章节标题" --context-before 0 --context-after 3 --detail with-ids
```

### 残留检查

```bash
# 检查用户要求删除的内容是否还有残留
lark-cli docs +fetch --doc "DOC_ID" --scope keyword --keyword "要删除的关键词" --context-before 0 --context-after 0
# 返回content为空说明已清除
```

---

## 验证不通过时的处理

1. **内容缺失**：补充对应章节，重新写入，重新验证。
2. **事实错误**：修正错误数据，必要时重新检索核验，重新验证。
3. **图片问题**：替换不合格图片，重新上传插入，重新验证。
4. **格式错误**：修复XML标签，重新写入，重新验证。
5. **残留未清**：定位残留block，用str_replace或block_delete清除，重新验证。

**验证通过前不得标记完成、不得交付。**

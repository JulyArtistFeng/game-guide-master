# 飞书XML写作模式

写正文XML前完整读取。本文档定义攻略文档的标准XML结构、标签用法和章节模板。

---

## 文档整体结构

```
<title>游戏名 + 攻略类型（扩充详解版）</title>
<callout>文档说明（核验时间、适用对象、当前版本）</callout>
<h1>一、总述</h1>
...
<h1>二、开局</h1>
...
<h1>📚 进阶系统详解 · 使用指南</h1>（可选，大量进阶章节时加）
<table>28章目录速查表</table>
<h1>十一、XX系统</h1>
...
```

---

## 每章标准结构

每个 h1 章节必须遵循以下结构：

```xml
<h1>章节编号、章节名</h1>
<img path="@./chapter_image.jpg" caption="图片说明"/> （可选，1~2张）
<callout emoji="🎯" background-color="light-blue" border-color="blue">
<p><b>本章怎么用：</b>用1~3句话说明这章解决什么问题、读者应该怎么读、新手优先做什么。</p>
</callout>
<h2>小节标题</h2>
<p>正文内容</p>
<table>...</table> （数据表格化）
<callout emoji="⚠️" background-color="light-red" border-color="red">
<p><b>注意：</b>关键风险、易错点、版本差异。</p>
</callout>
```

### "本章怎么用"callout 范式

必须回答三个问题：
1. 这章解决什么问题？（"来这里是为了修远古科技站、挖铥矿"）
2. 读者应该怎么读？（"先看进入方式，再看科技站修复"）
3. 新手第一动作是什么？（"第一次进务必带够护甲、光源和回血"）

## 标签用法速查

### callout（高亮提示框）

```xml
<callout emoji="🎯" background-color="light-blue" border-color="blue">
<p><b>标题：</b>内容</p>
</callout>
```

常用配色：
- 蓝色（light-blue/blue）：本章引导、说明
- 红色（light-red/red）：警告、风险、易错点
- 绿色（light-green/green）：完成确认、正面提示
- 紫色（light-purple/purple）：特殊系统、进阶内容
- 黄色（light-yellow/yellow）：版本差异、待确认项

### table（数据表格）

```xml
<table>
<thead><tr><th><p>列1</p></th><th><p>列2</p></th><th><p>列3</p></th></tr></thead>
<tbody>
<tr><td><p>数据</p></td><td><p>数据</p></td><td><p>数据</p></td></tr>
</tbody>
</table>
```

**必须表格化的内容**：配方、掉落物、属性对比、怪物HP/伤害、时间周期、物品分类。

### grid（多栏布局）

```xml
<grid columns="3">
<grid-column><p><b>标题1</b><br/>内容</p></grid-column>
<grid-column><p><b>标题2</b><br/>内容</p></grid-column>
<grid-column><p><b>标题3</b><br/>内容</p></grid-column>
</grid>
```

用于：关键资源速览、三件套推荐、多选项并列。

### ol / ul（列表）

```xml
<ol>
<li><p>第一步：...</p></li>
<li><p>第二步：...</p></li>
</ol>
<ul>
<li><p>要点1</p></li>
<li><p>要点2</p></li>
</ul>
```

流程步骤用 ol（有序），要点列举用 ul（无序）。

### img（图片）

```xml
<img path="@./image.jpg" caption="图片说明文字"/>
```

- path 用 `@./` 相对路径，基于运行 lark-cli 时的 CWD。
- caption 简短说明画面内容。
- 插入位置：h1 标题之后、callout 之前。
- **图片质量标准（按类型区分）**：
  - **纯游戏画面**（场景、战斗、Boss、地形、角色、建家布局等）：不设最低分辨率硬门槛，画面主体清晰可辨即可，低分辨率也保留——游戏画面的价值在于视觉展示，不要强行用文字代替。
  - **含密集文字/表格/数据的图片**（食谱表、配方图、科技栏、制作栏、地图、属性面板等）：必须 ≥1920×1080 且文字放大后清晰可读。模糊的含文字图片一律弃用，对应数据改用文档内 table 呈现，图片只保留纯场景展示。

## 写作风格规范

### 语言

- 用玩家能听懂的话，不堆砌术语；首次出现的术语给简短解释。
- 指令性语言："做XX"、"先XX再XX"，不用"建议你可以考虑XX"。
- 数字精确：配方写清材料数量，周期写清天数，不掉率写"约X%"。

### 内容深度

- 每个机制讲清"是什么→怎么触发→有什么用→注意什么"。
- 流程类内容（如"月圆取得格罗姆"）拆成 Step 0~Step N，每步有明确动作和判断标准。
- 对比类内容（如"两种切斯特形态"）用表格并列，不用散文。

### 不确定项处理

- 无法确认的数字写"约X（以游戏内为准）"或直接"以游戏内为准"。
- 版本差异用callout注明："XX是单机版规则，联机版为YY"。
- 不编造任何配方、掉落率、HP数值。

---

## 常见错误

1. **XML标签不配平**：写入前检查每个开标签有对应闭标签。
2. **callout里直接放文字不用`<p>`包裹**：必须 `<p>文字</p>`。
3. **表格单元格不用`<p>`包裹**：`<td><p>内容</p></td>`。
4. **章节没有"本章怎么用"callout**：每章必须有。
5. **数据用散文罗列不用表格**：配方/掉落/属性一律表格。
6. **图片caption为空或过长**：10~30字说明画面即可。
7. **在正文里写内部执行过程**：不要出现"已路由到XX"、"根据skill规则"等。
